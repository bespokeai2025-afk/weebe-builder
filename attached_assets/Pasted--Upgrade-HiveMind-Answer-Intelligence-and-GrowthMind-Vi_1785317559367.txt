# Upgrade HiveMind Answer Intelligence and GrowthMind Video Generation

Upgrade the production AI architecture for HiveMind and GrowthMind across the WEBEE platform.

This is an implementation, migration and verification task. Do not merely change model labels in the interface.

The completed system must:

1. Upgrade HiveMind’s actual answer-generation models from GPT-4o.
2. Route executive-level requests to an appropriate GPT-5.6 model.
3. Preserve fast and affordable processing for lightweight background work.
4. Implement genuine Veo 3.1 video generation in GrowthMind’s Content Studio.
5. Confirm which API account and project are being billed.
6. Record the exact provider, model, tokens, generation cost and request status for every AI operation.
7. Remove silent fallbacks, fake provider labels and unverified model claims.

## Part 2 — Verify OpenAI Billing and Credentials

Determine which OpenAI credential is used in production.

Safely verify:

* Key fingerprint, showing only the final four characters
* OpenAI organisation or project associated with the request
* Environment in which the key is configured
* Whether development and production use different keys
* Whether the key is overridden at workspace level
* Whether requests pass through another AI provider
* Whether an OpenAI-compatible proxy URL is configured
* Whether requests are being cached
* Whether failed OpenAI requests silently fall back

## Part 3 — Introduce a Central Model Registry

Create one central, typed model registry.

Do not hardcode model IDs across separate pages and functions.

Configure:

```text
HIVEMIND_CHAT_MODEL=gpt-5.6-terra
HIVEMIND_EXECUTIVE_MODEL=gpt-5.6-sol
HIVEMIND_BACKGROUND_MODEL=gpt-5.6-luna
HIVEMIND_FALLBACK_MODEL=gpt-5.5

GROWTHMIND_VIDEO_RENDER_MODEL=veo-3.1-generate-001
GROWTHMIND_VIDEO_DRAFT_MODEL=veo-3.1-fast-generate-001
```

Before activating a model, perform an availability check using the configured provider credentials.

Where GPT-5.6 access is unavailable for the current OpenAI project, fall back explicitly in this order:

```text
gpt-5.6-terra
→ gpt-5.5
→ gpt-5.4
```

Do not silently fall back to GPT-4o.

Record every fallback event and display it in authorised diagnostics.

## Part 4 — Upgrade HiveMind Answers

Migrate HiveMind from GPT-4o to the OpenAI Responses API.

Use:

### Normal HiveMind conversation

```text
Model: gpt-5.6-terra
Reasoning effort: low
```

Use this for:

* Normal questions
* Business summaries
* Operational updates
* Explanations
* Analytics interpretation
* Tasks and recommendations
* General platform assistance

### Executive and complex work

```text
Model: gpt-5.6-sol
Reasoning effort: medium
```

Use this for:

* Strategic decisions
* Cross-department analysis
* Complex campaign diagnosis
* Financial implications
* Business-risk assessment
* Multi-step plans
* Root-cause analysis
* Decisions involving several WEBEE departments
* High-value recommendations
* Requests explicitly asking for a deep analysis

Allow `high` reasoning only for genuinely difficult requests.

Do not use maximum reasoning by default because it increases latency and expense.

### Lightweight background work

```text
Model: gpt-5.6-luna
Reasoning effort: none or low
```

Use this for:

* Classification
* Sentiment labelling
* Lead categorisation
* Simple extraction
* Business DNA tagging
* Intent recognition
* Notification summaries
* Routing decisions

Do not use the lightweight model for important executive answers.


* Shot list
* Voiceover copy

* Camera direction

```text

```

for premium video generation.

Use:

```text

```

for drafts, previews and lower-cost iterations.

Do not label Gemini text generation as Veo video generation.

## Part 14 — Failure Handling

* Record the original failure
* Apply only an approved fallback
* Record the fallback model
* Preserve the conversation
* Do not return a fake success
* Do not mislabel the answer
* Do not expose credentials
* Prevent duplicate tool actions
* Prevent duplicate video jobs

For video generation failures, allow the user to:

* Retry
* Adjust the prompt
* Select Fast mode
* Reduce resolution
* Return to the storyboard

Do not automatically create repeated paid generations without approval.
