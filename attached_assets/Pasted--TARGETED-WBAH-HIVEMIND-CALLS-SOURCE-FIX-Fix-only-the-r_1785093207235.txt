## Confirmed root cause

In `fetchFullPlatformData`, the calls block still reads the standard `calls` table for every workspace.

For WBAH:

- Standard `calls` table has 89 lifetime rows and 0 today.
- Real WBAH calls are stored in `wbah_calls`.
- `wbah_calls` has 720 calls today.
- HiveMind therefore incorrectly says there were no calls.

The existing `isWbah` branch already overrides leads and bookings correctly, but it does not override the calls block.

## Required fix

Extend the existing `isWbah` branch so all WBAH call metrics come from `wbah_calls`.

Use the configured WBAH timezone:

`Europe/London`

Do not use:

`setHours(0,0,0,0)`

Build the correct London-local day window and convert it to UTC before querying.

For the verified day, the window was:

`2026-07-25 23:00 UTC` inclusive  
to  
`2026-07-26 23:00 UTC` exclusive

Calculate this dynamically for every date and handle BST/GMT correctly.
