# 2. INBOUND BUZZCHAT REPLY MUST UPDATE THE CRM

When a genuinely NEW inbound customer WhatsApp reply is received, automatically connect it to the canonical WEBEE CRM/Lead system.

**New inbound BuzzChat message**

→ deduplicate provider webhook
→ resolve workspace
→ normalize customer phone number
→ locate canonical contact/lead
→ update/create appropriate CRM relationship
→ record BuzzChat activity
→ surface person in Leads/CRM pipeline
→ create configured notification
→ make same state immediately available to mobile

# 3. CONTACT / LEAD MATCHING

Do not create duplicate leads every time someone sends another WhatsApp message.

Match in this order where applicable:

1. existing canonical BuzzChat/contact relationship
2. external CRM/contact ID
3. normalized E.164 phone number
4. existing WEBEE lead/contact mapping
5. other existing canonical identifier

Phone matching must normalize formatting such as:

* `+44...`
* `0044...`
* local formats

according to existing project rules.

Always scope matching to the correct workspace.

# 4. IF AN EXISTING LEAD EXISTS

If the person already exists as a WEBEE lead:

* BuzzChat conversation ID
* latest inbound WhatsApp message
* latest reply timestamp
* unread/reply state
* message source
* WhatsApp provider
* requires human follow-up where applicable

Prefer an activity/event relationship rather than bloating the lead row if the existing architecture already supports activities.

# 5. IF CONTACT EXISTS BUT NOT AS A LEAD
