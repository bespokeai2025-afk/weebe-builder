# 2. CENTRAL ENFORCEMENT — NOT FEATURE-BY-FEATURE PATCHES

Do not add separate intelligence fixes inside every feature while leaving the central creation paths unchanged.

Create one authoritative server-side enforcement layer through which every Mind-generated operation must pass.

Equivalent architecture:

Mind instruction
→ universal instruction interpreter
→ objective resolver
→ entity resolver
→ context and evidence loader
→ capability resolver
→ intelligence packet
→ quality gate
→ work order
→ task plan
→ execution
→ approval
→ provider/internal action
→ verification
→ evidence
→ monitoring
→ learning

Enforce this at the shared services that create:

- Recommendations
- Work orders
- Tasks
- Executions
- Actions
- Campaigns
- Content projects
- Reports

No feature may bypass the universal layer with a direct database insert or isolated helper.

Add protections at several levels:

1. Shared service validation
2. Task/work-order creation middleware
3. Execution dispatch validation
4. Database constraints where appropriate
5. UI safeguards
6. Automated architecture tests

A prompt instruction alone is not sufficient.
