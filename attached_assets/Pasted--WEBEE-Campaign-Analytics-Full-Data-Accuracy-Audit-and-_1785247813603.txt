# WEBEE Campaign Analytics — Full Data Accuracy Audit and Fix

The campaign data currently displayed in WEBEE is incorrect. Totals do not reliably match the real calls, durations, outcomes or campaign usage.

Audit and fix the complete campaign analytics pipeline for:

* WBAH
* Every existing WEBEE client
* Standard client workspaces
* Future client workspaces
* Inbound campaigns
* Outbound campaigns
* Retell-based campaigns
* CRM-connected campaigns

This is an implementation task. Do not only analyse the problem or provide recommendations. Inspect the production architecture, identify the causes, implement the fixes, backfill the correct data and prove that the resulting totals reconcile with the authoritative source records.

## Non-Negotiable Accuracy Rule

Campaign analytics must only display totals calculated from verified production call records.

Do not use:

* Mock data
* Placeholder data
* Estimated totals
* Frontend-calculated totals
* Sample data
* Hardcoded values
* Incomplete cached totals
* Lead counts as a substitute for call counts
* Agent-level totals incorrectly treated as campaign totals

If the underlying provider data is incomplete or unavailable, show an explicit data-integrity warning. Never silently invent or estimate missing figures.

## Preserve Existing Functionality

Do not break:

* Existing Retell integrations
* WBAH call ingestion
* Standard client call ingestion
* Existing CRM integrations
* n8n workflows
* Live calls
* Call queues
* Webhooks
* Lead creation
* Qualification logic
* Calendar bookings
* Existing analytics filters
* Existing reports
* HiveMind access
* Workspace security
* Mobile or web analytics pages

Extend and repair the existing system safely rather than replacing working functionality without evidence.

## Identify the Root Causes

Specifically test for:

* Duplicate calls
* Missing calls
* Calls assigned to the wrong campaign
* Calls assigned using agent ID instead of campaign ID
* One agent being used across several campaigns
* Retell batch IDs not being stored
* Campaign IDs being lost during sync
* Campaign names changing after calls occurred
* Archived campaigns being excluded incorrectly
* Incorrect workspace scoping
* WBAH records being mixed with standard account logic
* Seconds being displayed as minutes
* Milliseconds being interpreted as seconds
* Duration being rounded before aggregation
* Only connected calls being counted
* Voicemail calls being excluded
* Failed calls with valid duration being excluded
* Zero-duration attempts being treated as billable minutes
* Test calls being included
* Deleted calls remaining in summaries
* Date filters using the wrong timestamp
* UTC and local timezone boundaries
* Reports using different logic from the Analytics Centre
* Stale cached values
* Failed or partial Retell syncs
* Pagination stopping before all provider records are retrieved
* API rate limits causing incomplete imports
* Repeated webhook events creating duplicates
* Historical records never being backfilled
* Frontend filtering changing totals after aggregation
* Incorrect joins multiplying call rows
* Multiple lead records causing one call to be counted repeatedly

Do not proceed with a superficial UI-only fix.

# Phase 2 — Establish the Authoritative Source of Truth

For provider-generated calls, use the provider’s unique call record as the authoritative source.

For Retell calls, use the Retell call ID as the primary deduplication key unless the real production architecture contains a stronger verified provider identifier.

Each call should have one canonical analytics record containing, where available:

```text
provider_call_id
workspace_id
campaign_id
campaign_name_snapshot
agent_id
batch_id
call_direction
call_status
started_at
ended_at
duration_seconds
connected_duration_seconds
disposition
sentiment
qualified_status
booking_status
lead_id
is_test
is_deleted
source_provider
source_updated_at
analytics_updated_at
```

Do not rely on campaign names as unique identifiers.

Store the campaign name as a historical snapshot for reporting, but use the immutable campaign ID for attribution.

## Source Priority

When the same call appears in multiple sources, apply a documented source-priority rule.

Recommended priority:

1. Authoritative provider call record
2. Verified local canonical call record
3. Provider webhook event
4. WBAH-specific call record
5. CRM call record
6. Lead or data-record reference

Lower-priority records may enrich a call but must not create an additional call count.

# Phase 3 — Fix Campaign Attribution

Campaign totals must be based on the campaign that actually generated or received the call.

Use the strongest verified identifier available:

1. Internal WEBEE campaign ID stored when the call was triggered
2. Provider batch or campaign ID mapped to a WEBEE campaign
3. Campaign ID included in provider metadata or dynamic variables
4. Campaign reference stored on the canonical call
5. CRM campaign ID mapped to a WEBEE campaign
6. Agent-to-campaign mapping that was valid at the time of the call

Do not attribute calls solely by current agent ownership when the same agent can serve multiple campaigns.

When an outbound call is started, ensure the system sends and stores:

```json
{
  "workspace_id": "verified-workspace-id",
  "campaign_id": "verified-campaign-id",
  "campaign_run_id": "verified-run-id",
  "lead_id": "verified-lead-id"
}
```

Store these identifiers immediately, before the call completes.

For inbound calls, use the phone number, routing configuration, agent assignment and campaign routing rules that were valid at the time of the call.

Calls that cannot be confidently attributed must appear under:

```text
Unassigned Campaign
```

Do not hide these calls or silently assign them to a convenient campaign.

Add an admin-only reconciliation view showing why each unassigned call could not be mapped.

# Phase 4 — Create One Canonical Analytics Calculation Service

Create or repair one server-side analytics service that powers:

* Campaign Analytics
* Workspace Analytics
* Reports
* Automated reports
* PDF exports
* CSV exports
* Spreadsheet exports
* HiveMind
* Mobile analytics
* Web analytics

Do not maintain separate conflicting calculation logic across each surface.

All analytics queries must be scoped server-side by the authenticated `workspace_id`.

## Calculation Rules

### Total Calls

```text
Count of unique valid provider_call_id values
```

### Total Duration

```text
Sum of authoritative duration_seconds
```

### Total Minutes Used

```text
Sum of authoritative duration_seconds ÷ 60
```

Sum seconds first and divide afterwards.

Do not round each call individually before summing.

### Average Call Duration

```text
Total valid duration seconds ÷ number of calls with valid duration
```

### Connected Calls

Use a verified provider or system connection status.

Do not assume every completed call connected to a person.

### Connected Minutes

Use connected or billed duration where the provider supplies it.

If only total call duration exists, label the metric accurately as total duration rather than connected duration.

### Qualification Rate

```text
Unique qualified calls ÷ unique eligible completed calls
```

Do not divide lead records by calls.

### Booking Rate

```text
Unique calls producing a confirmed booking ÷ unique eligible connected calls
```

A booking must have a real booking ID or confirmed calendar response.

### Conversion Metrics

Ensure every conversion is attached to a unique call ID so repeated lead updates do not create repeated conversions.

# Phase 5 — Correct Date and Timezone Handling

Store timestamps in UTC.

Apply the workspace timezone only when calculating reporting boundaries and presenting dates.

For WBAH, verify the configured reporting timezone rather than assuming it.

The following filters must return exact, consistent results:

* Today
* Yesterday
* This week
* Last week
* This month
* Last month
* Last 7 days
* Last 30 days
* Custom date range

Define whether the selected end date is inclusive and apply the same rule everywhere.

Recommended server query pattern:

```text
started_at >= range_start_utc
AND started_at < range_end_utc
```

Do not mix `created_at`, `updated_at`, `ended_at` and `started_at` between reports unless the metric explicitly requires it.

Use the call start timestamp as the default reporting timestamp unless the existing product specification says otherwise.

# Phase 7 — Deduplicate Existing Data

Create an idempotent deduplication process.

For duplicate provider call IDs:

* Keep one canonical record
* Merge valid enrichment data
* Preserve the most authoritative duration
* Preserve the correct workspace
* Preserve the verified campaign
* Remove duplicate aggregate contributions
* Do not delete audit history without logging it

Check for duplicated rows caused by joins to:

* Leads
* Call outcomes
* Campaign members
* Bookings
* CRM activities
* Post-call extraction records
* Sentiment records

Use `COUNT(DISTINCT provider_call_id)` where appropriate, but fix the underlying joins rather than relying only on distinct counts to hide data errors.

Add a database uniqueness constraint where safe:

```text
workspace_id + source_provider + provider_call_id
```

Do not add the constraint until existing duplicates have been safely resolved.

## Reconciliation Formula

For each workspace and date range:

```text
Unique provider calls
=
Assigned campaign calls
+ Unassigned calls
+ Explicitly excluded calls
```

For duration:

```text
Provider duration seconds
=
Assigned campaign duration seconds
+ Unassigned duration seconds
+ Explicitly excluded duration seconds
```

Every excluded call must include a documented exclusion reason.

For campaign totals:

```text
Sum of all campaign calls
+ Unassigned calls
=
Workspace total calls
```

```text
Sum of all campaign duration
+ Unassigned duration
=
Workspace total duration
```
