# 1. CURRENT CRITICAL FAULTS TO FIX

The existing platform currently displays evidence of architectural fragmentation.

Observed faults include:

1. HiveMind creates recommendations and task records but does not perform the underlying work.
2. Approving a task can merely change its status from Suggested to Approved or In Progress.
3. Assigned Minds such as GrowthMind are sometimes stored only as labels and do not receive executable jobs.
4. The Tasks page and Action Approval Centre contain separate items that do not have an obvious parent-child relationship.
5. GrowthMind campaign proposals can appear in Actions while related GrowthMind tasks appear elsewhere.
6. Actions may show raw JSON payloads rather than meaningful business approval information.
7. Incomplete campaign drafts, including proposals with a null budget, can still show an Approve button.
8. The floating HiveMind voice/chat interface appears different from the full HiveMind Assistant.
9. The floating and full HiveMind interfaces may use different voices, prompts, memory, tools, conversations or endpoints.
10. The interface can say Operator mode is active while another section says Operator mode must be enabled.
11. Recommendations, Tasks, Actions, Campaign Proposals and Executions overlap without clear purposes.
12. Duplicate system notifications can be generated for the same unchanged issue.
13. Generic GrowthMind proposals are being created without enough Business DNA or real campaign evidence.
14. HiveMind can state that work is in progress when only task records were created.
15. Existing platform functions may be implemented but unreachable, disconnected, feature-flagged, partially wired or never invoked.

Fix these problems throughout the shared backend and web application.

Where mobile consumes the shared backend, expose all required secure APIs and shared records so mobile uses the exact same orchestration state.

- Blocked
- Failed
- Cancelled
- Rejected

Rules:

- Approved does not mean Executing.

- Failed requires the real error and retry status.
- A user cannot manually mark an AI-executed task complete without an authorised override.
- A generic Complete button must not be shown for active Mind work.
- Retrying must launch or resume a real execution.
