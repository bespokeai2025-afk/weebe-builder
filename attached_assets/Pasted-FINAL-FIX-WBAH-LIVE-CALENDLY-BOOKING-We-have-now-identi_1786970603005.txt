We have now identified the exact booking issue.

The existing live flow is correct:

Get Available Slots

However there are TWO logic bugs that must be fixed.

==================================================
1. STOP PASSING current_date AS preferred_date BY DEFAULT
==================================================

The current Retell node sends:

preferred_date = {{current_date}}

on every availability check.

This is wrong.

It means a caller who has NOT requested a particular date is only searching the day the call happens.

That caused Neil's Saturday call to search:

2026-08-15

and return zero.

But this problem is not specific to weekends.

It could also fail:

- after business hours
- when today's appointments are full
- late on Friday
- on holidays

Correct behaviour:

IF the caller explicitly asks for a date:
→ preferred_date = requested date

IF the caller has NOT requested a specific date:
→ preferred_date = null

Then the backend searches for the NEXT genuinely available appointments.

Do not substitute {{current_date}} for a missing date preference.

==================================================
2. EXTRACT ACTUAL REQUESTED DATE
==================================================

If the caller says:

"What do you have Tuesday?"

send Tuesday's actual date.

If caller says:

"Wednesday afternoon?"

send Wednesday's date plus the relevant time preference if supported.

If caller simply says:

"What's your next appointment?"

send:

preferred_date = null

==================================================
3. BACKEND FALLBACK
==================================================

The WeeBespoke endpoint should also be defensive.

If preferred_date is null:

search forward across the configured future availability window.

If preferred_date is supplied:

search that requested date.

If no appointments exist on the requested date:

return that result PLUS next available alternatives where appropriate.

Do not falsely say:

"No appointments are available in the next week"

when only one date was checked.

==================================================

==================================================

The existing endpoint is generating times such as:

Use Calendly's genuine event-type available-times logic so only actually bookable appointment start times are returned.

The availability query must respect:

- buffers
- scheduling rules
- calendar conflicts
- minimum notice
- event-specific availability

Do not manufacture appointment starts locally.
